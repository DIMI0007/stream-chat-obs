# Стандарт документации плагинов OTMOPOZOK

## Языки и файлы

- `README.md` — главная страница на русском.
- `docs/README_EN.md` — полная английская инструкция, с теми же возможностями, ограничениями и версией.
- В начале обоих файлов — переключатель **Русский · English**. Русская ссылка ведёт на корневой README, английская — на файл в docs.
- Пользовательские описания новых изменений и выпусков пишутся на русском. Имена API, кода и общепринятых технических терминов сохраняются.
- Документы для внешних сервисов могут быть на английском; из русского README они получают понятную подпись.

## Единое оформление

1. Заголовок с названием плагина, короткой строкой о пользе и переключателем языков.
2. Одинаковые статические значки совместимости: версия OBS, Windows x64, нативный Qt. Не показывать значок успешной проверки вместо реального статуса.
3. Сразу после введения — честный статус: что реализовано, что проверено в OBS, что ещё требует проверки.
4. Одна основная ссылка на скачивание и ссылка на установку. Для тестового архива явно указывать, что это тестовая сборка.
5. Настоящий скриншот текущего интерфейса с подписью версии или пометкой о тестовом стенде. Если такого снимка нет, не подменять его макетом.
6. Возможности, установка, подключение сервисов, ограничения, диагностика, документация, поддержка и лицензия.
7. Короткие абзацы, последовательные шаги; таблицы — для совместимости и статуса. Избегать широких сеток из множества скриншотов.

## Версии и готовность

- Версия должна совпадать в buildspec.json, интерфейсе, манифесте архива и инструкции.
- Указывать конкретную проверенную конфигурацию OBS/Windows/Qt.
- Сборка CI, загрузка в OBS, ручной тест отправки и получение настоящего события — разные проверки. Не заменять одну другой.
- Не называть сборку подписанной без проверки подписи всех EXE/DLL в пакете.
- Для каждой новой сборки сохранять исходный commit, SHA256 и результат проверки подписи.
- Ограничения сторонних API и состояния «разрабатывается» / «требует проверки» должны быть одинаковыми в обоих языках.

## Безопасность и поддержка

- Не добавлять в README, скриншоты, примеры, CI и issue реальные токены, OAuth-секреты или вебхуки.
- Для обращения в поддержку запрашивать версию, код безопасной ошибки и отредактированный журнал.
- Инструкция включает обновление и удаление плагина без удаления настроек пользователя.
- Политика конфиденциальности описывает реальные сетевые подключения и хранение данных.
- Уведомления о донатах и ссылки на поддержку проекта не должны мешать установке и диагностике.
